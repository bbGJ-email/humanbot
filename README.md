# HumanBot — 超拟人 AI BOT 系统

基于 [BoxIM SDK](https://github.com/nichengfuben/boxim-sdk) 构建的**情感陪伴型**拟人 AI BOT 系统。

目标不是「让 AI 看起来像人」，而是**让它在行为层面无法被区分**：会累、会困、会睡着后真正掉线、会不耐烦、会骂人、会冷战、会道歉后继续别扭、会有自己的生理周期、会不时改个签换头像、会半夜发一条莫名其妙的消息。

## 核心特性

### 1. 行为拟人化（不是措辞拟人化）

| 维度 | 实现 |
|---|---|
| 打字节奏 | 基础延迟 + 每字延迟，随精力下降变慢；困倦时再乘 2 倍 |
| 消息分条 | 超过 45 字自动拆条，条间有 0.5~1.5 秒间隔 |
| 错别字 | 5% 概率手滑（同音字替换），1.5 秒后「*」纠正 |
| 撤回重发 | 5% 概率发完觉得不对，撤回后重发 |
| 消息合并 | 对方连发多条时才统一回复，模拟「读完再回」 |
| 从不告别 | 对话结束时直接不回或只回一个字 |
| 深夜变话痨 | 23:30 后回复变长、变感性 |

### 2. 睡眠与真实掉线

- 四个状态：`AWAKE` → `DROWSY` → `ASLEEP` → `WAKING`
- **睡着时真正断开 WebSocket**（不是装作不回），对方能看到你离线
- 入睡时间由 5 重扰动决定：个体偏移 σ、星期效应、情绪联动、睡眠债、7% 通宵
- 永不整点入睡
- 半夜有 20% 概率醒来看一眼又睡
- **醒来后统一处理睡眠期间的消息**：按时间分层，越早的消息回复越随意

### 3. 情绪与冲突

- 四维情绪：愉悦 / 精力 / 亲密 / 压力
- 不满度 0~100，五个等级：

| 区间 | 状态 | 表现 |
|---|---|---|
| 0-14 | 正常 | 无异常 |
| 15-39 | 不爽 | 回复变短，语气变冷 |
| 40-64 | 冷嘲 | 阴阳怪气，用「哦」「行」「随便你」 |
| 65-84 | 冷战 | 数小时不回，或只回一个字 |
| 85+ | 拉黑边缘 | 明确表达要删好友 |

- **会骂人**：L2-L5 分级的骂人话库（去人格化、翻旧账、撂狠话）
- **会道歉但不轻易原谅**：对方道歉后先冷 5~15 分钟，再考虑给台阶
- 时间自动降级：不满度会随小时数缓慢自然衰减

### 4. 生理周期（性别门控）

- 仅当 `persona.identity.gender == female` 时启用，人设为男性时**模块完全跳过**（`physio_enabled` 在初始化时一次性计算）
- 周期 23~33 天随机，20% 概率本月很轻
- 四阶段：月经期 / 卵泡期 / 排卵期 / 黄体期
- 与不满度耦合：月经期 ×1.8、卵泡期 ×0.7、排卵期 ×0.9、黄体期 ×1.2（第 24 天后 ×1.5）

### 5. 反 AI 三层防御

```
预防  →  负向提示词（20 条禁令）写进 system prompt
检测  →  17 个检测器打分：总分 ≤30 通过 / ≤60 改写 / >60 重新生成
修复  →  定向改写 + 6 种噪声注入（补句、口语赘余、标点软化…）
```

检测项包括：书面连接词、排比结构、过度共情、服务腔、总结收尾、中英夹杂、完美标点、emoji 滥用、句长均匀度、词汇丰富度异常、段落对称性、Markdown 残留、谄媚开场、免责声明、说教腔、模板化结尾、字数异常。

**被问「你是不是 AI」时四级递进**：困惑 → 不耐烦 → 反问 → 发火（含不满度直接 +5/+15/+30/+45）。

### 6. 记忆三层

| 层 | 内容 | 存储 |
|---|---|---|
| 工作记忆 | 最近 12 轮对话 | 内存 |
| 档案记忆 | 长期事实（名字、职业、喜好） | SQLite + 向量 |
| 情节记忆 | 具体事件（"3月说要去旅行"） | SQLite + 向量 |

- 用 **API 做向量嵌入**（OpenAI 兼容 `embeddings` 接口），失败自动退化为 2-gram 关键词打分
- 检索打分：`相似度×0.7 + 重要度×0.2 + 时间新近度×0.1` + 置顶加权
- 抽取前有廉价预过滤（触发词命中才调模型）

### 7. 图片系统（免注册 API）

- **生成**：Pollinations.ai `https://image.pollinations.ai/prompt/{prompt}`，无需 Key
  - 上游限流约每 15 秒一次，代码内置重试 3 次 + UA 头 + 15 秒间隔
- **检索**：Bing 图片，解析 `murl&quot;:&quot;` 字段，无需 Key
- 提示词刻意写成「随手拍」风格并附负向词，避免出图过于精致而暴露 AI 感

### 8. 表情包（内置表情库直连）

BoxIM 平台自带 12 个表情包专辑、1000+ 张表情。系统直接走官方接口拉取，不依赖第三方图源：

| 接口 | 用途 |
|---|---|
| `GET /sticker/albums` | 列出所有专辑 |
| `GET /sticker/stickers/{albumId}` | 列出专辑内全部表情 |
| `GET /sticker/stickers/search` | 按名字模糊搜索 |

发送方式：表情就是一条 `type=7` 的消息，但 **content 格式有个坑**。

> ⚠️ **SDK 的表情格式在这个站点上是错的**
>
> SDK 的 `MessageBuilder.sticker()` 生成 `{"stickerId": 742}`，但盒子IM 的 Web 客户端
> 渲染表情时读的是 **`content.imageUrl`**（见 ChatView 的 STICKER 分支
> `<img :src="content.imageUrl">`）。用 SDK 那个格式发出去，对方只看到
> **「[动画表情] undefined」**。
>
> 实际客户端发送时用的是**整个表情对象**：
> ```json
> {"id":742,"albumId":18,"name":"2643",
>  "imageUrl":"https://.../xxx.gif",
>  "thumbUrl":"https://.../xxx.webp",
>  "width":100,"height":100}
> ```
> 本项目按客户端的行为来拼 content，不走 `send_sticker()`，而是用
> `send_private_raw()` / `send_group_raw()` 自己控制消息体。

**撤回也要注意**：`recall_private_message(message_id)` 必须传**真实消息 id**。
发送接口返回 `{"code":200,"data":{"id":19032818,...}}`，要从 `data.id` 取；
传 0 或本地 id 只会得到「消息不存在」。所以 `send_text()` 现在返回消息 id，
撤回直接用这个返回值。

**为什么要自己打标签**：1065 张里有一半的名字是 `2643` 这种纯数字，直接按名字匹配等于没用。
所以启动时会同步目录并自动打情感标签（18 类：开心 / 喜欢 / 难过 / 生气 / 疲惫 / 睡觉 /
招呼 / 疑惑 / 吃 / 可爱 / 忙 / 赞 / 惊讶 / 害羞 / 冷淡 / 围观 / 活力 / 早安），
选图时先按场景算标签，再从对应标签池里挑。

| 场景 | 结果 |
|---|---|
| 晚安 | 呼呼大睡 / 蜷缩睡觉 / 先睡一会 |
| 早安 | 早安 |
| 「哈哈哈哈」 | 比耶 / 逗猫棒 / 耶 |
| 「我失恋了呜呜」 | 委屈 / 寂寞 / 流泪 / 大哭 |
| 不满度 75 | 溜了溜了 / 逃跑 / 杂鱼 / 纸片人 |
| 「好累」 | 瞌睡 / 葛优躺 / 无精打采 / 犯困 |
| 「你吃饭了吗」 | 吃瓜 / 橘子 / 寿司卷 / 大饱口福 |

三种发送形态：

| 形态 | 触发 | 概率 |
|---|---|---|
| 文字 + 表情 | 正常回复后随手补一个 | 18% |
| 只发表情 | 对方只发了情绪（"哈哈哈""无语"） | 12% |
| 冷战只发表情 | 不满度 ≥65 时，用表情代替装死 | 55% |

另有冷却（25 秒）、每日上限（60 张）、7 天内不重复发给同一个人。

### 9. 群聊主动参与感兴趣的话题

BOT 会在群里**自己判断该不该插嘴**，而不是只等被 @。

三层判断：

**① 兴趣画像（自动生成）** — 直接读人设，不手写配置。
默认人设「沈晚」是旧书店店员、爱看书喝手冲、玩单机 RPG、想养猫，
系统自动提取出话题画像：`上班 / 咖啡 / 宠物 / 旅行 / 游戏 / 读书`。

**② 话题热度（越聊越热）** — 每个群单独累积话题热度，半衰期 6 小时自然衰减。
她参与过的话题升温更快，所以"这个群最近老在聊游戏"会让她更容易接话。

| 场景 | 权重变化 |
|---|---|
| 第 1 次聊游戏 | 0.174 |
| 连聊 6 次后 | 0.329 |

**③ 参与惯性 + 插话抑制** — 模拟"聊到一半"的真实状态：

| 距上次发言 | 惯性 | 无关话题的权重 |
|---|---|---|
| 0 秒 | 1.00 | 0.350 |
| 2 分钟 | 0.90 | 0.290 |
| 5 分钟 | 0.50 | 0.200 |
| 10 分钟 | 0.00 | 0.050 |

刚回过又马上回会被降权（×0.45），避免像刷屏机器人。

完整决策树：

```
① 底座权重
   @她            1.00
   提到名字        0.80
   感兴趣的话题    0.72 × 兴趣得分（人设 0.55 + 群热度 0.30 + 话题具体度 0.15）
   完全无关        0.05

② 修正
   + 参与惯性      momentum × 0.30
   + 话题连续性    累积热度，上限 +0.25
   × 插话抑制      90 秒内刚回过 → ×0.45
   × 刷屏抑制      1 分钟超 5 条 → ×0.50
```

效果：**光聊一句游戏不会立刻跳出来，聊几句热度上来之后她才会自然加入**。

### 10. 账号自主行为

- 按情绪换个性签名（8 套签名库，1~3 天一次）
- 每周约 5% 概率换头像（走图片生成）
- 主动发起生活事件分享（24 小时硬上限；连续 3 次被无视则 7 天静默）
- 完整账号操作：加好友、拉黑、设备注、置顶、免打扰、删会话、建群、退群、收藏、投诉

### 11. 深度防封

- 每日发送上限（默认 300）
- 最小发送间隔
- 群里刷屏自动降权
- 会话级暂停开关

### 12. 语音通话

- 收到语音/视频来电后，用 **关系 + 情绪 + 时段** 综合判断接不接：
  陌生号不接、还在生气拒接、凌晨只接亲密关系、正在通话占线
- **振铃延迟**：绝不秒接，真人要放下手上的事，2.5~7s 随机（刚睡醒更久）
- **填充词掩盖延迟**：LLM 超过 800ms 先播「嗯……」，2 秒沉默很假，
  「嗯……」之后的 2 秒非常自然；接起语/填充词启动时预热，零延迟出声
- **打断让步**：对方抢话就停下听，不像多数 AI 那样自顾自说完
- TTS 用 edge-tts（晓晓成熟音色，情绪映射语速/音调），
  STT 用模型站 telespeechasr（备用 sensevoicesmall）
- 视频来电统一用「摄像头坏了」挡回去（BOT 没有真实摄像头）
- 通话后情绪结算（语音比文字影响大）、记忆沉淀摘要、
  聊够 5 分钟推进关系阶段、未接来电醒来后回拨

> 依赖：`aiortc`（WebRTC 媒体）、`av`（音频编解码）、`numpy`、
> `edge-tts`（中文 TTS）。均已列入 `requirements.txt`。
> 控制台「通话记录」页可查看接听决策、对话转写与事件时间线。

## 快速开始

### 环境要求

- Python **3.9+**（BoxIM SDK 支持 3.8~3.14）
- 网络可访问 `boximchat.com` 与你配置的模型接口

### 一键启动

**Linux / macOS**

```bash
chmod +x start.sh
./start.sh
```

**Windows**

```bat
start.bat
```

脚本会自动完成：定位 Python → 创建 `.venv` → 安装依赖 → 建目录 → 探测空闲端口 → 启动。

启动后终端会打印：

```
==============================================================
  HumanBot - Super-human-like AI Bot System
==============================================================
  Console   : http://127.0.0.1:8800
              http://192.168.1.23:8800          (LAN)
              http://203.0.113.45:8800      (WAN)
  Username  : admin
  Password  : <随机生成的强密码>
              [NEW] password generated on first launch
  Bots      : 1 account(s)
==============================================================
```

密码也会写入 `data/console.txt`（权限 600），首次启动后请立即修改。

### 启动参数

| 参数 | 说明 |
|---|---|
| `--port 8899` | 指定控制台端口（默认自动探测 8800~8900） |
| `--host 127.0.0.1` | 指定绑定地址（默认 `0.0.0.0`，即外网可访问） |
| `--no-bots` | 只启动控制台，不登录 BOT |
| `--reset-password` | 重新生成强密码 |

### 首次配置流程

1. 复制配置模板并填入你自己的账号与模型：

   ```bash
   cp config.example.yaml config.yaml
   ```

   编辑 `config.yaml`，至少改这两处：

   - `boxim.username` / `boxim.password`：你的 BoxIM 账号
   - `model.providers[].api_key`：你的模型接口 key

2. 启动：

   ```bash
   ./start.sh          # Linux / macOS
   start.bat           # Windows
   ```

启动后：
1. 用打印的用户名密码登录控制台
2. （可选）去 **API 配置** 点「全部测试」，确认各供应商都通
3. （可选）去 **人设编辑** 调整人设，用「实时预览」看成稿效果

### 配置你的 BoxIM 账号

`config.yaml` 的 `boxim` 段填你的账号：

```yaml
boxim:
  username: 你的用户名
  password: 你的密码
```

**账号昵称和人设名可以不一致**。群聊别名会自动同时认人设名、自称、IM 昵称和账号名这四类名字——别人在群里 @ 她、或者用任意一个名字提到她，她都能被叫到。

如果你希望 IM 里显示的昵称也叫「沈晚」，把 `config.yaml` 改成：

```yaml
boxim:
  sync_nickname: true    # 登录后自动把 IM 昵称改为 persona 的名字
```

默认是 `false`——因为改名会真的动到你的账号，而且不改也不影响功能。

## 控制台

绑定 `0.0.0.0`，局域网/公网可直接访问。首次启动自动生成 20 位强密码（排除易混字符 `Il1O0o`，强制混合大小写数字符号），以 PBKDF2-SHA256（20 万次迭代）哈希存储。

| 页面 | 功能 |
|---|---|
| **仪表盘** | 运行状态、情绪曲线（24h 四维折线）、消息量、BOT 列表、实时事件流 |
| **会话** | 私聊/群聊上下文查看、手动发消息、手动发图、会话级暂停回复、清空该会话记忆 |
| **人设编辑** | 结构化表单 / YAML 原文双模式编辑 + 实时预览（真实调用模型，展示原始输出、最终输出、AI 感得分对比、命中的检测项、最终 system prompt 全文） |
| **情绪 / 冲突** | 四维情绪实时值、不满度、冷战剩余时间、手动注入（5 个滑块 + 5 个预设：开心/疲惫/冷淡/生气/濒临决裂）、情绪历史表 |
| **记忆** | 三层记忆浏览、语义检索、新增/编辑/删除/置顶 |
| **睡眠 / 周期** | 当前状态机、睡眠计划、睡眠债、睡前留言、生理周期阶段与倍率、睡眠记录表、强制入睡/唤醒/补拉离线 |
| **表情包** | 目录浏览（按专辑 / 标签 / 名字搜索）、选图预览（填心情和对方的话，看会挑哪张）、发送记录、一键同步 |
| **群聊参与** | 人设兴趣画像、群列表与热度话题、话题热度明细、每群独立关键词、参与度参数热调 |
| **API 配置** | 供应商 CRUD + 连通性测试（单个/全部）、任务路由可视化配置、预算与超限行为 |
| **用量成本** | 按任务 / 按日期统计调用次数、花费、平均延迟 |
| **图片库** | 缓存浏览、手动生成 |
| **沙盒 / 反 AI** | 不发消息跑完整链路、17 检测项命中排行、一次通过率、最近检测明细 |
| **日志** | 实时事件流（WebSocket 推送）+ 操作审计表 |
| **系统设置** | BoxIM 连接、拟人化强度（延迟/分条/错别字/撤回/上限）、睡眠参数、记忆与媒体阈值 |

控制台的读写路径设计为：**只操作数据库与命令队列，不直接触碰 SDK 对象**，避免多线程竞态。

## 模型配置

项目内置**多供应商路由 + 自动故障转移**，支持同时配置多个 OpenAI 兼容接口，
按任务类型分流到不同模型：

- 正式回复、记忆抽取、情绪计算、反AI改写、图片理解、向量嵌入等任务，可分别指定不同供应商
- 主供应商报 429 / 5xx / 超时 / 返回空时，自动沿故障转移链换下一个重试
- 配置走 `config.yaml` 的 `model` 段（模板见 `config.example.yaml`），或控制台「API 配置」页

```yaml
model:
  providers:
    - id: main
      name: 你的主模型
      base_url: https://你的接口/v1
      api_key: 你的key
      model: 模型名
      enabled: true
  routing:
    reply_generate: main
  failover:
    - backup
```

嵌入建议选支持中文的向量模型，维度需与 `memory.embedding_dim` 一致。

## 人设

人设是这套系统的灵魂。默认人设「**沈晚**」是一个 24 岁的杭州旧书店店员，包含：

- **性格矛盾** 5 组（社交/表达/能力/情绪/依赖）——有矛盾才是真人
- **语言指纹**：单条 ≤45 字、偏好省略号、绝不用颜文字和「哈哈哈哈哈」、称呼随关系阶段变化
- **7 个怪癖**：聊到书会连发 3-4 条、被夸奖就转话题、23:30 后变话痨、聊到家庭生硬切断、从不告别、被问是不是 AI 会发火、对方久不回就变冷
- **生活事件**：生日不主动说、周一会睡到中午、交房租会低落、室友半夜做饭吵醒她
- **硬边界** 8 条

编辑方式：控制台「人设编辑」页支持结构化表单和 YAML 原文双模式，保存后热更新。

**换性别**：把 `identity.gender` 改成 `male`，生理周期模块自动失效（`physio_enabled` 在启动时一次性求值）。

## 部署到 VPS

`deploy/` 目录里是现成的部署资产，已在 Ubuntu 22.04 + BT-Panel 环境实测通过。

### 目录与虚拟环境

```bash
# 代码放 /www/wwwroot/humanbot，和 BT-Panel 的其他站点并列
cd /www/wwwroot/humanbot
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

### systemd 常驻服务

```bash
cp deploy/humanbot.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now humanbot
```

服务已配置 `Restart=always`（崩溃自动拉起）、`KillSignal=SIGINT`（优雅停机，
给足时间把离线游标与情绪状态落库）、stdout/stderr 分别落到
`logs/service.log` 与 `logs/service.err.log`。

常用命令：

```bash
systemctl status humanbot      # 状态
systemctl restart humanbot     # 重启（改完 config.yaml 后需要）
journalctl -u humanbot -f      # 跟随 systemd 日志
tail -f logs/service.log       # 跟随应用日志
```

### 日志轮转

代码里的日志用 `RotatingFileHandler`（5MB × 3）自轮转；systemd 捕获的那两个
文件不受 Python 影响，需要额外配：

```bash
cp deploy/logrotate.conf /etc/logrotate.d/humanbot
```

> 不加这一步的话，`service.log` 会随着 BOT 常驻无限增长，几周就能吃掉几个 G。
> 同理 `assets/media/` 里的出图也会累积，代码里已按"最多保留 200 张"自动裁剪。

### 控制台暴露到外网

控制台默认监听 `0.0.0.0`，直接开端口即可访问 `http://<IP>:8899`。
如果想要域名 + HTTPS，`deploy/nginx.conf` 是一份可用的反代模板：

```bash
cp deploy/nginx.conf /www/server/panel/vhost/nginx/<你的域名>.conf
# 按需替换 server_name 与证书路径
nginx -t && nginx -s reload
```

模板里有两个容易漏的点：

- **WebSocket 必须放行** —— 控制台的事件流走 `/ws/console`，缺少
  `Upgrade` / `Connection` 头就会连不上，页面能打开但日志面板是死的
- **`proxy_read_timeout` 要调大** —— 事件流是长连接，默认 60s 会被掐断

> BT-Panel 环境下注意：跑着的是 `/www/server/nginx/sbin/nginx`，
> 而 `PATH` 里的 `nginx` 可能是系统那份。改完配置要用
> `/www/server/nginx/sbin/nginx -c /www/server/nginx/conf/nginx.conf -s reload`，
> 直接敲 `nginx -s reload` 会因 pid 路径不同而静默失败。

### 线程模型

```
主线程          → FastAPI / uvicorn（控制台）
BOT 线程        → asyncio 事件循环（所有 SDK 异步调用）
工作线程池      → 编排链（阻塞操作：模型调用、HTTP、SDK 同步方法）
心跳线程        → 每 20 秒 tick（状态转换 / 生活事件 / 主动消息检查）
```

`EventBus` 通过 `loop.call_soon_threadsafe` 把工作线程的事件桥接给 WebSocket 客户端。

### 关键工程约束（来自 SDK 实测）

1. **没有静态事件钩子**：必须用 `_ws.on(event, handler)` 注册，且没有 `off`，所以 handler 内部必须自守护（SDK 会吞掉异常）。
2. **`send_text` 是同步阻塞 HTTP**：在事件循环里直接调用会卡死心跳，必须走线程池或 `asend_*`。
3. **历史接口无分页**：`get_*_message_history` 只支持 `min_seq_no`/`max_seq_no` 或 `local_ids`，二选一。
4. **SDK 自带指数退避重连**（`delay * 2^n`，封顶 300 秒），断线期间消息会丢，必须自己做游标 + `load_*_offline_message` 补偿。

## 常见问题

**Q: 启动后 BOT 显示离线？**
检查 `config.yaml` 里的账号密码，或在控制台「系统设置」里填写后重启进程。账号配置改动需要重启才生效。

**Q: 控制台打不开？**
看启动横幅打印的端口。默认在 8800~8900 区间自动探测，被占用会自动换端口。公网访问需确认云服务器安全组放行该端口。

**Q: 预览/回复报模型错误？**
控制台「API 配置」页点「测试」查看具体错误。常见原因：Base URL 少了 `/v1`、Key 无效、模型名不存在、余额不足。

**Q: 模型偶尔报错 / 超时？**
免费接口限流是常态。项目已内置故障转移链——主模型 429 / 超时 / 返回空内容时会自动切到备用供应商重试，偶发抖动不会变成一次失败回复。可在控制台「API 配置」页调整这条链。

**Q: 想让 BOT 不休眠？**
`config.yaml` 里 `sleep.enabled: false`，或在控制台点「强制唤醒」并关闭睡眠。

**Q: 图片生成一直失败？**
Pollinations 是免费公共接口，忙时限流严格。代码已内置 3 次重试 + 15 秒间隔，仍失败属正常现象，稍后再试。

**Q: 怎么改成男性人设？**
控制台「人设编辑」→ 性别选 `male` → 保存。这样生理周期模块会自动失效。

**Q: 密码忘了？**
停掉进程，运行 `./start.sh --reset-password`，新密码会重新打印并写入 `data/console.txt`。
